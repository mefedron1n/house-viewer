# Несколько проектов с разными IFC — план и точка продолжения

## Задача пользователя

Каждая существующая функция должна работать для нового проекта с другим IFC.
Работать законченными этапами; сохранять здесь результат, проверки и следующий шаг,
чтобы продолжить после перерыва. Не считать всю задачу завершённой после одного этапа.

## Исходное состояние (2026-09-15)

В рабочей копии уже были незакоммиченные изменения пинов, фильтрации комнат,
планов, фотографий и камеры. Их нужно сохранять. Последнее исправление камеры
отменяет старую анимацию при установке общего вида; стартовое вращение убрано.

Подтверждённые препятствия:

- `/api/rooms` и материалы комнат используют один общий каталог и папку `rooms/`.
- Фронтенд не передаёт проект в запросах комнат и их материалов.
- Редактирование и удаление автоматических комнат иногда работают только через
  общие ключи localStorage и теряются после повторного анализа.
- Начальный список `HOUSE_ROOMS` содержит комнаты демонстрационного дома.
- Замечания к фото принимают только идентификаторы комнат из общего каталога.
- Загрузка IFC из просмотрщика идёт через общий `/api/models`; GLB открывается
  как временный blob, вместо сохранения в текущем проекте.
- Метаданные IFC загружаются однократно. При замене модели возможно применение
  старых комнат к новой геометрии.
- Перевод координат IFC через одну позицию корня GLB требует проверки: у проекта
  `897f87847f87007404183277` геометрический пол имеет Y≈0.2, а вычисленная высота
  помещения Y≈1.79. GLB и IFC могут уже иметь разные исходные смещения.
- Видимость крыши/стен и геометрический анализ требуют проверки на другом IFC,
  включая отсутствие IfcSpace, разные оси и несколько этажей.

## Этапы и критерии

1. **Изоляция комнат и материалов** — выполнено и проверено.
   Каталог из метаданных текущего IFC; отдельные CRUD и файлы для каждого проекта;
   передача проекта во всех запросах; заметки к материалам с IFC GUID;
   тест двух проектов с одинаковыми ID комнат и проверка прав доступа.
2. **Каталог и интерфейс** — синхронизация выполнена и проверена.
   Общий актуальный каталог для 3D, фото, рендеров и плана; сохранение ручных правок;
   отсутствие демонстрационных комнат в новых проектах; геометрический fallback.
3. **Загрузка/замена IFC и координаты** — предстоит.
   Сохранение через API текущего проекта; обновление метаданных и состояния;
   согласование GLB/IFC; корректные пол, камера, изоляция и пины.
4. **Сквозная проверка** — предстоит.
   Два разных IFC: загрузка, комнаты, камера, стены/крыша, изоляция, пины,
   фото/PDF, рендеры, планы, совмещение, статусы, удаления, перезагрузка страницы.

## Правила сохранности

- Не перезаписывать существующие пользовательские модели и материалы ради теста.
- Интеграционные проверки используют временное хранилище и тестовые аккаунты.
- Общий режим без `?project=` остаётся совместимым.
- Перенос старых общих материалов в проекты требует однозначной принадлежности;
  не приписывать одинаковые room ID сразу нескольким проектам.
- После каждого этапа обновлять этот файл: изменения, команды проверок, оставшиеся
  ограничения и точный следующий шаг.

  Список обновляется сразу, не дожидаясь загрузки материалов; поздние ответы
