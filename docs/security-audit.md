# Проверка безопасности Roomark — 14 сентября 2026

Область: исходный код, Docker/Nginx, локальные тесты API на временных данных. Это не проверка работающего внешнего сервера и не нагрузочная атака. Список ниже — план из 70 проверок. В этом проходе устранены конкретные находки из таблицы результатов; наличие пункта в плане не означает, что он уже проверен. «Не найдено» означает только отсутствие подтверждения в проверенной области.

## Применение и границы

Изменены файлы проекта и локальные npm-зависимости. Рабочие контейнеры автоматически не перезапускались. Чтобы применить зависимости, ограничения Docker и конфигурацию Nginx к локальному стенду:

```sh
docker compose up -d --build --force-recreate ifc-api web
```

Команда кратковременно перезапускает сервисы и сохраняет именованный том с данными. Ограничение RAM 2 ГБ / 2 CPU нужно проверить на ваших крупных IFC-моделях и при необходимости увеличить.

Это не полный пентест всех 70 пунктов. Вне подтверждённых исправлений остаются:

- Глобальное пространство без `?project=` и глобальные материалы `/api/rooms` исторически публичны; они не стали приватным многопользовательским хранилищем. Приватность гарантируется проверками владельца только для маршрутов, привязанных к проекту. Миграция глобальных материалов в проекты требует отдельного изменения модели данных.
- Квоты постоянного дискового хранения, распределённые лимиты для нескольких процессов, защита канала от объёмного DDoS, TLS/боевой домен, CDN/WAF, резервные копии и системные библиотеки образов здесь не проверены полностью. Лимиты приложения не заменяют защиту провайдера от сетевого DDoS.
- CSP пока разрешает inline-скрипты; внешние ссылки внутри GLB и все ветви DOM-рендеринга не проходили полный аудит.
- Если прежняя конфигурация раздачи репозитория была доступна из интернета, следует сменить находившиеся там секреты: закрытие URL не отзывает уже полученные копии. Факт прошлой утечки не устанавливался.
